Storage figures include shutdown/fault effects and cannot be mixed with version-1 live snapshots. It retains evidence after guarded owned cleanup. Smoke timings are not performance results.

The completed hosted campaign [39739708895](../../../../coursework/BENCHMARK-EVIDENCE.md) ran source `3044ff1dbc72cb606eb39f07509ec0dffe1babf7`. All 140 trials passed cleanup, with 12,271 of 12,271 offered operations finished. Each of the 27 comparison cells ran five times. See the [curated cell medians, ranges and raw summary hash](../../../../coursework/benchmark-full-39739708895.json).

GET timing uses a warm-cache file and includes full-byte SHA-256 verification. PUT timing ends at the acknowledged response; each written file is then read back and verified outside timing. The 16 MiB cells use four offers per repetition, so the concurrency setting of 16 does not create 16 concurrent requests, and a p99 from four samples is not a tail-confidence estimate. The range oracle asserts an exact byte slice per trial, but the response bytes are not retained in the receipts.

The 5, 20 and 80 transactions/s sweeps and the 120-second run at 80/s completed without loss. Stability p99 was 5.689688 ms for transaction latency and 0.204087 ms for dispatch lag. The run did not reach saturation at 80/s. The `<100 ms` dispatch and `<5 s` transaction p99 checks are engineering screening thresholds, not production SLAs. The 2 MiB recovery journey took 92.935 seconds end to end, while repair remained blocked by the unchanged upstream loopback endpoint guard. This journey time is not repair latency.
