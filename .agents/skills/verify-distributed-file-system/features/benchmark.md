# Frozen native storage benchmark

`python -m unittest discover -s coursework -p test_benchmark.py -v` checks deterministic data and timeout outcomes. `python coursework/benchmark.py smoke` reuses the maintained Workbench, launches real master/filer/three volumes, performs warm upload/read plus one verified PUT/GET/DELETE lifecycle and a range oracle. It retains evidence after guarded owned cleanup. Smoke timings are not performance results.

`python coursework/benchmark.py benchmark` requires isolated Linux. Version1 freezes seed421, sizes4KiB/1MiB/16MiB, concurrency1/4/16 and separate PUT/GET/metadata cells. All27 cells run five times with reverse order. Baseline is concurrency1 with identical size/operation. Each cell owns fresh stores, warms one file, and measures16 operations, or4 for16MiB to stay inside unchanged volume limits. PUT returns are verified by full readback outside timing; GET timing includes full-byte SHA256 validation; metadata timing is a stat+listing transaction with two requests, not one metadata RPC. An independent post-timing range oracle covers each size. Read cells are explicitly warm-cache repeated reads of one file. Writes use fresh unique paths.

Offered-load5/20/80 lifecycle transactions/s run10s with16 outstanding slots; each transaction includes PUT+verified GET+DELETE+404 check. Declines remain explicit. Highest zero-loss rate with dispatch-p99<100ms and transaction-p99<5s gets120s stability. Useful bytes count one payload per transaction, not bidirectional wire traffic. The actual unchanged storage limits can reject accumulated deleted needles; report this envelope. A separate2MiB recovery cell invokes the existing real volume-loss, restart and explicit repair journey. Repair stays blocked by default endpoint guards, with exact guard text and unchanged placements. No security policy is weakened.

Raw `.local/benchmark-*/summary.json` links each `.local/benchmark-trial-*/benchmark/result.json`, preserving source/dirty/environment, workload, payload hash, all intended-arrival samples/outcomes, operation scope, byte oracles, manifests and Linux CPU/RSS every100ms. Storage records apparent bytes and filesystem allocated blocks of the whole owned data tree before cleanup, plus live payload bytes. This includes replicated needles/indexes/metadata/deleted retention. Workbench's containment checks and all-owned process cleanup run before data deletion; receipts survive. Capabilities are not introduced.

Separate `profile` mode uses existing master/volume cpuprofile flags and requires four nonempty profiles after graceful owned shutdown, plus generator cProfile. Filer hot-path CPU remains unprofiled. Do not optimize it from other-service profiles. Manual read-only Ubuntu workflow builds full native weed, drives self-check/smoke/campaign and uploads selective receipts/logs/profiles. No measured performance result is yet published.
